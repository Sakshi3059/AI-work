    │

## Explain Payload URL

Example

```text
https://jenkins.company.com/github-webhook/
```

Breakdown:

* `https://` → Secure HTTP protocol.
* `jenkins.company.com` → Hostname (where Jenkins is running).
* `/github-webhook/` → Endpoint exposed by the Jenkins GitHub plugin to receive webhook events.

---

## What is a Webhook?

A webhook is an **HTTP callback**.

One application sends an HTTP request to another when an event occurs.

Example:

```
Developer pushes code
        │
        ▼
GitHub
        │
HTTP POST
        ▼
Jenkins
        │
Runs pipeline
```

# A good interview answer

> "I configured a Jenkins Pipeline using 'Pipeline script from SCM'. Jenkins cloned my GitHub repository, located the Jenkinsfile using the configured script path, and executed the pipeline. I integrated GitHub Webhooks by exposing Jenkins through ngrok for local development. GitHub sent HTTP POST requests to `/github-webhook/`, which the Jenkins GitHub plugin received and used to trigger the pipeline automatically. In production, ngrok would be replaced with a stable Jenkins URL such as `https://jenkins.company.com/github-webhook/`. For building every branch automatically, I would use a Multibranch Pipeline instead of a regular Pipeline."

This explanation covers both the practical setup you implemented and the production architecture interviewers typically expect.
